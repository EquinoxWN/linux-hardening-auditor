## Security review fixes (2026-11-12)

| Finding | Fix | Test |
|---|---|---|
| `NOPASSWD :` (space before the colon, valid for sudo) was not flagged; `Defaults !authenticate` was ignored | the tag pattern allows whitespace before `:`; `!authenticate`, global (last one wins) or scoped (`Defaults:user`, `@host`, `>runas`, `!cmnd`), fails SUDO-001 | `test_nopasswd_tag_allows_whitespace_before_the_colon`, `test_defaults_not_authenticate_counts_as_nopasswd`, `test_authenticate_turned_back_on_globally_passes` |
| Defaults were split on every comma, ignoring double quotes and backslash escapes | a small tokenizer (`split_defaults`); an unterminated quote is an error | `test_sudoers_defaults_split_respects_quotes_and_escapes`, `test_sudoers_unterminated_quote_is_an_error` |
| Relative `include` targets resolved against `/etc`; `%h` not handled | resolved against the including file's directory, as sudo does; `%h` is reported as an error, `%%` is a literal `%` | `test_sudoers_relative_include_resolves_against_the_including_file`, `test_sudoers_host_name_escape_is_an_error_and_double_percent_is_literal` |
| The ssh output cap was checked only after all output was read | `run_command` reads both pipes in chunks with `Popen` and reader threads, kills the process once either passes 1 MiB, keeps the timeout | `test_run_command_kills_a_process_once_output_passes_the_cap` and three more `run_command` tests |

## Quality control (DMAIC)

| Phase | This repository |
|---|---|
| Define | Linux hosts drift from a baseline and their effective settings are easy to misread (sshd first value wins, sudo include rules). M1 counts when SSH, sudo, PAM, sysctl, file modes and running services are read from a fixture tree, the local host or SSH, and each control is a validated YAML rule ([RFC 0001](../rfc/0001-design.md)). |
| Measure | `pytest`, ruff, `mypy --strict`, `pip-audit`, `lha rules validate` and the three fixture audits on an Intel Core i7-13700H with Windows 11: 167 passed, 0 failed; verdict sets as in the table above. |
| Analyze | The first test run found one real defect: the path pattern used `re.match` with `$`, which accepts a trailing newline, so `/etc/x\n` passed validation and could have reached a remote shell command. A Windows symlink test skipped silently, which left the tree-escape guard unchecked locally. |
| Improve | All validation patterns use `fullmatch`; the escape test uses a directory junction on Windows (no extra rights), so it runs everywhere and kills the "guard removed" mutant. |
| Control | `.tmp/check.sh` and CI run lint, strict types, the tests (with exact verdict sets per fixture), rule validation and `pip-audit` on every change; Dependabot PRs are paused and actions are SHA-pinned. |
