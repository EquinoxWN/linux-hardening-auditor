# Quality check against the 10 rules (2026-11-01 rule set, applied while building M1)

Run on 2026-11-12 on Windows 11 (Intel Core i7-13700H) with Python 3.14.5 in the repo's `.venv`.
Only the fixture trees under `tests/fixtures/hosts/` were audited; the live audit is CI-only.
Mutations were applied one at a time by a scratch script that restored each file right after its
test run (the script is not kept in the repository).

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Assume every call can fail | pass | External calls are `ssh` and `systemctl` subprocesses (`hosts.py`): each has a timeout (`subprocess.run(timeout=...)`, ssh `ConnectTimeout`); `run_command` reads stdout and stderr in chunks and kills the process once either passes 1 MiB (security review fix); ssh retries only exit 255 and timeouts, with backoff 0.5 s, 1 s, ... and at most 5 retries (`SshHost.run`), then raises `CollectError`. A read failure becomes an `error` finding and exit 3 (`audit.evaluate`), never a pass. No bare or broad `except` in `src/` (ruff `BLE`, `E722`, `S110` enabled). Tests: `test_ssh_retries_transport_failures_with_backoff_then_succeeds`, `test_ssh_gives_up_after_bounded_attempts`, `test_local_services_come_from_systemctl_and_failures_raise`. |
| 2 | Writes safe to retry | pass | The only write is the JSON report: temp file in the same folder, `fsync`, `os.replace` (`audit.write_json`); the temp file is removed on failure. `test_json_report_is_written_atomically_and_rewrites_cleanly` writes twice and checks identical content and no leftover file. Audited hosts are never written to (the `Host` interface has no write operation). |
| 3 | No race conditions | pass | Rules run one at a time; checks are frozen dataclasses. `run_command` uses two reader threads, each appending only to its own list and signalling through a `threading.Event`; the main thread reads the lists only after the threads are joined, and closes the pipes only once both readers have finished. |
| 4 | Don't trust the clock | pass | Audit duration uses `time.perf_counter`; `started_at` is `datetime.now(UTC)` (asserted to end in `+00:00`). Retry backoff uses `time.sleep` durations, not timestamps. |
| 5 | Read before changing | pass | The code reads no environment variables; every input is a CLI flag documented in the README. PyYAML `safe_load`, `importlib.resources.files`, `Path.is_relative_to` and `_winapi.CreateJunction` (tests, Windows only) exist in the installed versions (mypy strict passes). Every path in the docs exists (`audit_repo.py` link check). |
| 6 | Never break compatibility | pass | First release. The JSON report has a `tool` and `version` field so later formats can be told apart; the rule schema rejects unknown keys, so a future field is an explicit schema change, not silent. |
| 7 | One source of truth | pass | Rules live only in `src/linux_hardening_auditor/rules/*.yaml`; daemon semantics live only in `parsers.py`. Fixture metadata (`.lha-meta/`) is the single source for modes and services in a fixture and is named in the README. No caches. Python >=3.11 in `pyproject.toml`, 3.12 in CI, 3.11+ in the README. |
| 8 | Small changes, no secrets, validate input | pass | Secret scan: fixture `shadow` files hold only locked entries (`*`, `!`), no hashes. Validated input: paths (absolute, safe characters, no `..`, `fullmatch`), the ssh target (cannot start with `-`), port, timeout, retries, rule files (schema, size cap, `safe_load`, unique ids), stat manifests, unit names, `--only` ids; files over 1 MiB refused; the tree host refuses symlinks or junctions that leave the root. One dependency (PyYAML) for the YAML rules. |
| 9 | Tests that can actually fail | fixed | No tautologies, no unexplained skips (the live test is deselected by marker and runs in CI). Failure and invalid-input paths are covered for every public entry point. The first run caught a real defect: `re.match` with `$` let a path ending in a newline through validation; all patterns now use `fullmatch`. The symlink-escape test was skipped on Windows, so mutant 10 below would have survived locally; it now uses a directory junction and runs. 12/12 mutants killed. A later security review found four defects (NOPASSWD with whitespace and `!authenticate`, Defaults split on quoted commas, relative sudo includes and `%h`, the output cap checked after reading); each fix has a test, and 8/8 mutants that put the defects back are killed (one first survived because the test's message match also matched the fallback error; the match was made exact). A second review found a parser differential in scoped Defaults; the fix has 20 tests and 7/7 mutants killed. A third found `#-1` (a uid) cut as a comment; the fix has 8 tests and 3/3 mutants killed. |
| 10 | Re-verify | pass | Results below; CI not run yet (repository not pushed). |
